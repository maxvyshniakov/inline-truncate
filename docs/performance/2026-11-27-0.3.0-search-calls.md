# 0.3.0 → 0.6.0 measurement-call record

Confirms the 0.3.0 changelog claim (~−85% measurement calls on middle truncation and ~−37% on end truncation) against pre-0.3.0 (`v0.2.3`) and verifies that `0.6.0` retains those exact call counts with zero correctness failures (tracking `maxvyshniakov/inline-truncate#1`, TT-4).

## Method

Same host (`linux`/`x64`, AMD EPYC 9B45), bundled Inter (`InterVariable.woff2`), `chromium/159.0.8154.6`, 1280×800 viewport, DPR 1, `workload: text-truncate-v3`, `inline-measure@0.5.1` (registry). Each version was captured with `--scenario=algorithm --runs=9` (one warmup plus nine timed samples, followed by an untimed counter replay) using `--ref=v0.2.3`, `--ref=v0.3.0`, and the `v0.6.0` working tree under the identical harness.

The `highlight` scenario is excluded here because of the pre-existing Chromium 156 oracle drift noted in `maxvyshniakov/inline-truncate#1`; every `algorithm.*` scenario passed `correct: true` on all three revisions, and `v0.6.0` passed the full browser correctness oracle with 0 failures. (`v0.2.3` and `v0.3.0` each fail the eight `arabic/{end,start}/{60,90,120,160}` checks added in `v0.6.0`.)

- End truncation calls fall **−37.5% to −41.2%** (`0.588×–0.625×` of `v0.2.3`), matching the ~−37% claim.
- Between `v0.3.0` and `v0.6.0`, every scenario keeps the **exact same** Canvas call count (`0.0%` delta, `1.000×` ratio) and passes `--strict`.

## Ratio-based regression threshold

`scripts/perf/report.mjs` (`compare()`) enforces a ratio-based measurement-call regression check alongside the bootstrap timing interval check:

- Default threshold: `DEFAULT_MAX_CALL_RATIO = 1.05` (configurable via `compare(..., { maxCallRatio })` and CLI `--max-call-ratio=<n>`, requiring a finite number `>= 1`).
- For each scenario, `callRatio = beforeCalls > 0 ? afterCalls / beforeCalls : (afterCalls === 0 ? 1 : Infinity)`.
- `callRegression` triggers when `callRatio > maxCallRatio` (or when `beforeCalls === 0 && afterCalls > 0`), and `regression = timingRegression || callRegression`, so `--strict` exits nonzero on a measurement-call regression even when wall-clock timing stays within noise.
- Unit-tested in `scripts/perf/report.test.mjs` and `scripts/perf/options.test.mjs`.
