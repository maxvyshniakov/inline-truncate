# 2026-11-05 results

The accepted implementation selects emoji text through Canvas and verifies only the complete final candidate, retaining bounded native widths across resizes. Both final package-owned standalone comparisons pass `--strict` with all 17 scenarios correct and no detected timing regressions. Results below concern Inline Measure and Text Truncate; Data Grid performance is owned by another session. Native-session prototypes did not establish a package timing benefit over the accepted implementation and were not adopted.

## Standalone final results

Same host, bundled Inter, Chromium 156.0.8078.4, 1280×800 viewport and DPR 1. Each scenario warmed once and recorded five timed samples under an exclusive machine lease. Counter replay and correctness checks were outside timing.

| Scenario | Before ms | Text Truncate only ms | Both packages ms | Combined change |
| --- | ---: | ---: | ---: | ---: |
| `algorithm.middle.200` | 93.5 | 51.4 | 41.4 | -55.7% |
| `algorithm.repeated-labels.middle.200` | 84.0 | 48.6 | 38.0 | -54.8% |
| `algorithm.middle.long.50` | 2795.7 | 15.0 | 11.8 | -99.6% |
| `components.mount.middle.cold.200` | 213.7 | 106.5 | 91.3 | -57.3% |
| `components.mount.highlight-middle.cold.50` | 64.4 | 48.4 | 47.7 | -25.9% |
| `components.notifications.middle.warm.200` | 570.5 | 238.1 | 236.1 | -58.6% |
| `components.resize.middle.warm.200` | 568.5 | 253.5 | 234.0 | -58.8% |
| `components.mount.emoji-middle.cold.50` | 42.6 | 47.2 | 47.4 | 11.3% |

The emoji cold batch is 4.6–4.8ms slower than the original baseline (+10.8–11.3%). That raw increase is retained above; it is below the calibrated one-frame floor used for component settlement comparisons. It is not a claim of an emoji speedup. The rejected all-candidate DOM version took 80.9ms and 5,450 DOM reads; the final combined version takes 47.4ms and 150 DOM reads. The long-path batch deliberately stresses complexity and does not imply ordinary labels are 99% faster.

Stable-width notifications reduce Canvas calls from 138,900 to zero; the five-width resize journey reduces them to 7,459. Component wall time includes animation-frame settlement, so small CSS end/start and text/style-change percentages should not be sold as algorithm gains.

## Native-session experiments

The pooled-root prototype preserves three-engine correctness and exact native
widths, and reduces 50 native sessions from 50 body root additions/removals to
one. Direct comparisons against the accepted source in the **package-owned
harness** find no supported timing improvement in any of the 17 scenarios,
with either unchanged registry Inline Measure or the optimized Inline Measure
source. Both comparisons use matching method/environment/dependency identities.
Emoji cold mount is 47.2→47.4ms in isolation and 47.4→47.7ms combined; neither
is a supported change. The added shared-root lifecycle machinery is not adopted.

The separate lazy-box prototype removes an unnecessary computed-style read when
native widths are already cached. It has correctness/operation evidence, but no
separate package timing capture; no speedup is claimed and it remains unadopted.
Production stays `e917…`.

[Experiment archive](experiments/native-session-2026-11-05/README.md) retains the
patches, manifests, tests, width/counter evidence and direct accepted-versus-pooled
package comparisons. Data Grid performance belongs to another session and does not define this
package work.

## Rejected intermediate

Measuring every emoji candidate in the DOM took 80.9ms in the package’s 50-component cold emoji case, versus 42.6ms in the original baseline and 47.4ms in the accepted combined implementation. Its unchanged [raw data and summary](intermediate-dom-all/2026-11-05-results.md) remain historical evidence. They must not be attributed to the accepted final-native implementation.
