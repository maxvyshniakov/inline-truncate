# Rejected intermediate: all-candidate DOM, 2026-11-05

This intermediate implementation was rejected: its standalone cold emoji batch has a supported timing regression. Its results below remain historical evidence, not the accepted implementation. The replacement verifies only the final Emoji candidate and reuses native widths.

Text Truncate is faster for ordinary middle truncation, cold mounts and repeated resize work. Cold emoji measurement is intentionally slower because it now uses the DOM to avoid observed Canvas/paint discrepancies. These are separate outcomes; the strict timing command reports the emoji regression rather than hiding it.

All captures used the same host, bundled Inter font, 1280×800 viewport, DPR 1 and chromium/156.0.8078.4. Each scenario warmed once and recorded five timed samples under an exclusive machine lease. Counter replay and correctness checks were outside timing.

## What changed

- Lazy middle edges replace preparation of every hidden prefix and suffix. The complete candidate, including `...`, is measured so marker shaping is included.
- Mounted components retain segmented text and bounded width caches across width changes. Stable-width notification replay drops from 138,900 Canvas calls to zero; the five-width resize journey drops from 138,900 to 7,459.
- Class/text/query and font-load changes invalidate the relevant preparation. A late font cycle works when WebKit emits `loading` but omits `loadingdone`.
- Highlighted DOM is recreated when its text/query changes, fixing a retained inline-shaping defect demonstrated by a 0.625px difference between an existing node and a fresh clone. The ordinary unhighlighted text node remains stable.
- Emoji and unsupported CSS numeric/font-feature/variation/word-spacing/text-transform cases use a bounded-cache DOM measurement fallback. This is an accuracy correction, not a speed optimization.

## Accuracy and cost

The baseline fails the real DOM oracle for tabular numbers and retained highlighted text. The final candidate passes the full retained Inter/emoji width sweep (120–360px plus the previously failing boundaries), query-only change, resize, numeric features and delayed font load in Chromium, installed Firefox and WebKit.

The cold 50-row emoji scenario rises from 42.6 to 80.8 ms for Text Truncate alone (80.9 ms with both packages). It replaces 10,760 Canvas calls with 5,450 DOM reads. Both strict comparison commands return exit code 1 for this single supported timing regression. The other 16 scenarios have no supported regression under the recorded confidence intervals and timer/frame calibration.

Small CSS end/start and text/style-change percentages are dominated by frame settlement and should not be presented as meaningful algorithm gains. The long-path batch is a deliberate complexity stress case, not a claim that normal labels are 99% faster.
